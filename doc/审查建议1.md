## P0-1：二维码前端直接 `<img>`，JWT 不会带过去

当前：

```js
assetQrcodeUrl: (id) => `/api/assets/${id}/qrcode`,
```


```python
        content=asset_svc.qrcode_png(db, asset_id),
        media_type="image/png"
    )
```



### 前端改

`api/index.js` 增加：

```javascript
assetQrcode: (id) =>
  http.get(`/assets/${id}/qrcode`, {
    responseType: 'blob',
  }),
```

保留原来的：

```javascript
assetQrcodeUrl: (id) => `/api/assets/${id}/qrcode`,
```

也可以直接删掉 URL 版本，统一走 `assetQrcode()`。

然后 `AssetList.vue`：

```javascript
const qrUrl = ref('')

async function showQr(row) {
  current.value = row

  const resp = await api.assetQrcode(row.id)
  qrUrl.value = URL.createObjectURL(resp.data)

```

模板：

```vue
<el-dialog
```

# 二、二维码还有一个“产品级”问题

这比 JWT 更值得你注意。

你二维码现在编码的是：

```python
url = f"{settings.frontend_url}/#/assets/{asset.id}"
```

也就是**内部前端详情 URL**。

这意味着：

```text
手机扫码
 ↓
打开资产详情页
 ↓
前端调用 /api/assets/{id}
 ↓
需要 JWT
 ↓
手机没登录
 ↓
401
```

所以即使你解决了桌面端 `<img>` 的 JWT 问题，**手机扫码本身仍然可能要求登录**。

### 我建议这次作业这么处理

保留“内部资产二维码”，扫码后：

```text
未登录
→ 跳登录
→ 登录以后回资产详情
```

这样安全性更合理。

不要为了“扫码不用登录”而把：

```text
资产编号
当前领用人
联系方式
部门
```

这些敏感信息直接暴露成公共接口。

如果以后做正式产品，再设计：

```text
public_token
/
public/assets/{token}
```

只返回：

```text
资产编号
设备名称
型号
状态
```

不返回领用人等敏感信息。

# 四、把资产访问权限封装成统一方法

不要分别在：

```text
详情
生命周期
二维码
维修
```

里写一套套判断。

在 `services/asset.py` 增加：

```python
def get_accessible_asset(
    db: Session,
    asset_id: int,
    viewer,
) -> Asset:

    asset = db.get(Asset, asset_id)

    if asset is None:
        raise BizError("资产不存在", 40401)

    # 管理员可以访问全部资产
    if viewer_is_admin(db, viewer):
        return asset

    # 在库资产可以被普通用户查看
    if asset.status == "IN_STOCK":
        return asset

    # 其他状态只允许当前领用人查看
    assignment = db.scalar(
        select(AssetAssignment)
        .where(
            AssetAssignment.asset_id == asset_id,
            AssetAssignment.user_id == viewer.id,
            AssetAssignment.status.in_(ACTIVE_ASSIGNMENT_STATUS),
        )
    )

    if assignment is None:
        raise BizError("无权查看该资产", 40301)

    return asset
```

然后详情接口：

```python
@router.get("/{asset_id}")

        asset_id,
        viewer=user,

```

# 七、修 `create_repair()`

```python

```

改成：

```python
def create_repair(db, data, user, request=None):
    asset = db.get(Asset, data.asset_id)

    if asset is None:
        raise BizError("资产不存在", 40401)

    if asset.status == "SCRAPPED":
        raise BizError("已报废资产不能报修")

    if asset.status in ("PENDING_REPAIR", "REPAIRING"):
        raise BizError("该资产已在维修流程中")

    is_admin = viewer_is_admin(db, user)

    if not is_admin:
        # 普通用户只能报修自己当前领用的设备
        assignment = db.scalar(
            select(AssetAssignment)
            .where(
                AssetAssignment.asset_id == asset.id,
                AssetAssignment.user_id == user.id,
                AssetAssignment.status.in_(ACTIVE_ASSIGNMENT_STATUS),
            )
        )

        # 在库资产如果允许普通用户报修，可以放行；
        # 如果不允许，就只保留 assignment 条件。
```

# 九、P0：报废逻辑直接修掉

现在：

```python
if asset.status == "IN_STOCK":
    change_asset_status(asset, "PENDING_SCRAP")

if asset.status == "PENDING_SCRAP":
    change_asset_status(asset, "SCRAPPED")
```

导致一次调用可能：

```text
IN_STOCK
 ↓
PENDING_SCRAP
 ↓
SCRAPPED
```



但是你的前端明明已经设计成：

```text
待报废
↓
确认报废
```



所以这里直接改：

```python
def scrap_asset(
    db: Session,
    asset_id: int,
    operator=None,
    request=None,
) -> dict:

    asset = db.get(Asset, asset_id)

    if asset is None:
        raise BizError("资产不存在", 40401)

    if asset.status != "PENDING_SCRAP":
        raise BizError(
            "只有待报废资产才能确认报废"
        )

    change_asset_status(
        asset,
        "SCRAPPED"
    )

    write_log(
        db,
        operator.id,
        "ASSET_SCRAP",
        "ASSET",
        asset.id,
        f"确认报废 {asset.asset_code}",
        request,
    )

    db.commit()

    return get_asset(
        db,
        asset.id,
        viewer=operator,
    )
```

然后：

```text
POST /pending-scrap
```

只负责：

```text
IN_STOCK → PENDING_SCRAP
```

`POST /scrap`：

```text
PENDING_SCRAP → SCRAPPED
```

这就完全清楚了。

# 十、P1：到期提醒算法修掉

当前：

```python
milestone = next(
    (
        d
        for d in sorted(MILESTONES, reverse=True)
        if days <= d
    ),
    None
)
```



结果：

```text
29天 → 30天提醒

10天 → 30天提醒
8天  → 30天提醒
7天  → 7天提醒

```

虽然你用了“当天去重”，但第二天还是会再次提醒。当前 README 也明确写的是“30/7/1 天/逾期 + 当天同类型去重”。([GitHub](https://github.com/Han-Mao/asset-management))

### 直接改成里程碑触发

```python
days = (
    s.expected_return_time.date()
    - now().date()
).days

if days == 30:
    kind, label = "ASSET_EXPIRE_30D", "30天内到期"
elif days == 7:
    kind, label = "ASSET_EXPIRE_7D", "7天内到期"
elif days == 1:
    kind, label = "ASSET_EXPIRE_1D", "明天到期"
elif days < 0:
    kind, label = "ASSET_OVERDUE", "已逾期"
else:
    continue
```

这样：

```text
30天 → 发一次
7天  → 发一次
1天  → 发一次
逾期 → 每天一次
```

这个才符合用户直觉。
